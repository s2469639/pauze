01

스크롤을 숫자로 바꾸기

모든 스크롤 연출의 출발점은 "이 섹션을 몇 % 지났나"를 0~1 숫자로 만드는 거예요. 섹션 높이가 화면보다 크면, 섹션의 위쪽 끝이 화면 위로 얼마나 올라갔는지로 계산할 수 있어요.

assets/js/main.js

const clamp = (v, a = 0, b = 1) => Math.min(b, Math.max(a, v));
// v가 a~b 구간 중 어디쯤인지 0~1로 (구간 밖이면 0 또는 1)
const range = (v, a, b) => clamp((v - a) / (b - a));
// 천천히 시작해서 천천히 끝나는 곡선 (easeInOutCubic)
const ease = (t) => (t < 0.5 ? 4 * t * t * t : 1 - Math.pow(-2 * t + 2, 3) / 2);

function progressOf(el) {
  const r = el.getBoundingClientRect();          // 화면 기준 섹션 위치
  return clamp(-r.top / Math.max(1, r.height - innerHeight));
}

그다음 한 섹션의 진행도 f 하나로 여러 동작의 타이밍을 나눠요. 아래는 메인의 "향을 더하는 작은 루틴" 섹션 코드 그대로예요. range(f, 0.03, 0.11)은 "진행도 3%~11% 사이에서 0→1"이라는 뜻이고, 두 구간을 빼면 "올라갔다 내려오는" 모양이 돼요.

const f = progressOf($('#ritual'));
const capT  = range(f, 0.03, 0.11) - range(f, 0.38, 0.46);           // 캡 열렸다 닫힘
const flipT = ease(range(f, 0.5, 0.64)) + ease(range(f, 0.8, 0.92)); // 뒤집고, 다시 뒤집음
const mistT = range(f, 0.64, 0.7) - range(f, 0.8, 0.86);        // 향 안개 켜졌다 꺼짐
const step  = f < .17 ? 0 : f < .37 ? 1 : f < .48 ? 2 : f < .78 ? 3 : 4;   // 왼쪽 문구 01~05
stage.target.cap  = ease(capT);
stage.target.flip = flipT * Math.PI;   // 1 = 180도
실습 · 진행도 f를 움직여 보세요 01 캡을 열어주세요
f 0.25cap flip °mist

핵심: 연출을 "시간"이 아니라 "스크롤 위치"의 함수로 만들면, 사용자가 위로 다시 올려도 정확히 거꾸로 재생돼요. 별도 상태 관리가 필요 없어요.

03

글자가 차오르는 효과

위 실습의 문장이 단어마다 진해졌죠? 문장을 단어 단위 <span>으로 쪼갠 뒤, 진행도에 맞춰 앞 단어부터 불투명하게 만든 거예요. 실제 사이트는 같은 일을 GSAP에 맡겼어요.

assets/js/main.js

// 1) 쪼개기: "향은 계속 퍼지고" → <span class="w">향은</span> <span class="w">계속</span> …
el.innerHTML = el.textContent.trim().split(/\s+/)
  .map((w) => `<span class="w">${w}</span>`).join(' ');

// 2) 스크롤에 묶기: scrub:true = 스크롤 위치가 곧 애니메이션 진행도
gsap.fromTo($$('.w', el), { opacity: 0.12 }, {
  opacity: 1, stagger: 0.05, ease: 'none',
  scrollTrigger: { trigger: el, start: 'top 80%', end: 'bottom 45%', scrub: true },
});

제목이 아래에서 올라오는 효과

제목은 줄 단위로 쪼개서, 바깥 span은 overflow: hidden(창문), 안쪽 span은 yPercent: 110(창문 아래)에서 0으로 올려요. 창문 밖에 있다가 올라오니 "잘려서 등장"하는 느낌이 나요.

.line > span { display: block; }  .line { overflow: hidden; }
gsap.from($$('.line > span', el), { yPercent: 110, duration: 1.3, ease: 'expo.out', stagger: 0.09,
  scrollTrigger: { trigger: el, start: 'top 85%' } });  // scrub 없음 = 한 번 재생

scrub이 있으면 스크롤과 함께 앞뒤로 움직이고, 없으면 지점을 지날 때 한 번 재생돼요. "읽는 문장"은 scrub, "등장하는 제목"은 한 번 재생이 자연스러워요.

05

GSAP · ScrollTrigger · Lenis 역할 나누기

도구맡은 일이 프로젝트에서
GSAP값을 시간에 따라 부드럽게 바꾸는 엔진로딩 화면, 제목 등장, 버튼 자석 효과
ScrollTrigger"이 요소가 화면 어디에 오면" 애니메이션을 재생·되감기단어 차오르기, 사진 확대, 리뷰 카드 등장
Lenis휠 스크롤을 관성 있게 부드럽게사이트 전체 스크롤
직접 계산 (01장)매 프레임 진행도 → 3D 목표값리추얼, 컬러, 분해도 섹션

Lenis가 스크롤을 대신 굴리기 때문에, ScrollTrigger가 위치를 놓치지 않게 둘을 같은 시계에 묶어줘야 해요.

lenis = new Lenis({ lerp: 0.09 });             // 0.09 = 매 프레임 남은 거리의 9%씩 따라감
lenis.on('scroll', ScrollTrigger.update);         // 스크롤할 때마다 트리거 위치 갱신
gsap.ticker.add((t) => lenis.raf(t * 1000));   // GSAP의 프레임 시계로 Lenis를 돌림
gsap.ticker.lagSmoothing(0);

3D 섹션은 왜 ScrollTrigger 대신 직접 계산했을까요? 3D는 매 프레임 그려야 하고 값이 여러 개(뒤집기·캡·위치·크기)라서, 한 함수(updateStage)에서 한 번에 정하는 편이 읽기 쉽고 섹션끼리 충돌하지 않아요.

06

three.js 무대 세우기

three.js 장면은 항상 다섯 가지로 시작해요. 렌더러(캔버스에 그리는 화가), 장면(무대), 카메라(관객의 눈), 조명, 물체.

assets/js/scene.js

const renderer = new THREE.WebGLRenderer({ canvas, antialias: true, alpha: true }); // alpha: 배경 투명 → 페이지 색이 비침
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));   // 레티나 3배는 너무 무거워서 2로 제한
renderer.toneMapping = THREE.NeutralToneMapping;             // 밝은 부분이 하얗게 날아가지 않게

const scene = new THREE.Scene();
// 주변 반사용 '가짜 방' 환경맵 — 금속(브라스)과 유리가 반짝이는 이유
scene.environment = new THREE.PMREMGenerator(renderer).fromScene(new RoomEnvironment(), 0.035).texture;

const camera = new THREE.PerspectiveCamera(28, 1, 0.1, 50);  // 화각 28° = 망원 느낌, 왜곡이 적어 제품샷에 좋음
// 조명 3점: 왼쪽 위 따뜻한 키 라이트, 오른쪽 보조광, 뒤쪽 림 라이트(윤곽선)

물체를 그룹으로 감싸기

움직임마다 그룹을 하나씩 두면 계산이 단순해져요. 바깥 그룹은 뒤집기(Z축 회전), 안쪽 그룹은 천천히 도는 것(Y축 회전)만 맡아요. 둘을 한 물체에 섞으면 회전 순서가 꼬여요.

const flip = new THREE.Group();   // 뒤집기 담당
const spin = new THREE.Group();   // 자전 담당
flip.add(spin); scene.add(flip);
// 매 프레임: flip.rotation.z = state.flip;  spin.rotation.y = state.spin;

07

GLB 모델 쪼개고, 유리 넣기

받은 GLB는 메시 하나에 재질 하나로 통째로 붙어 있었어요. 그대로는 캡만 열거나 유리만 투명하게 할 수 없어서, 코드로 잘라냈어요.

1) file://에서도 열리게 base64로

브라우저는 더블클릭으로 연 HTML에서 다른 파일을 fetch하지 못하게 막아요. 그래서 GLB를 base64 문자열로 바꿔 <script>로 불러오고, 그 문자열을 다시 바이트로 돌려서 파싱해요.

const bin = atob(window.PAUZE_GLB), buf = new Uint8Array(bin.length);
for (let i = 0; i < bin.length; i++) buf[i] = bin.charCodeAt(i);
new GLTFLoader().parse(buf.buffer, '', onLoad);

2) 삼각형을 높이로 분류하기

3D 모델은 결국 삼각형 수만 개예요. 삼각형마다 세 꼭짓점 y값의 평균(중심 높이)을 보고, 캡(위 끝)·위 컵·유리 허리·아래 컵으로 나눴어요. 허리(|y| < 0.286)와 캡(y > 0.885)은 버리고 새로 만들어요.

for (let t = 0; t < pos.count; t += 3) {
  const cy = (pos.getY(t) + pos.getY(t + 1) + pos.getY(t + 2)) / 3;
  if (cy > CUT || Math.abs(cy) < GLASS) continue;   // 캡·허리는 버림
  keep[cy > 0 ? 0 : 1].push(t);                       // 위 컵 / 아래 컵
}

이 기준 숫자(0.885, 0.286)는 모델의 꼭짓점을 높이별로 훑어서 "반지름이 갑자기 바뀌는 지점"을 찾아 정했어요.

3) 유리는 '돌림판'으로 새로 만들기

모래시계 허리처럼 축을 중심으로 대칭인 모양은 LatheGeometry(도자기 물레)로 만들어요. 옆모습 선(반지름, 높이) 몇 개만 주면 360° 돌려서 입체를 만들어 줘요. 원래 모델의 허리 반지름을 재서 그대로 따라 그렸어요.

const prof = [[0, 0.098], [0.08, 0.135], [0.16, 0.19], [0.24, 0.25], [0.3, 0.298]]; // [높이, 반지름]
const glassGeo = new THREE.LatheGeometry(points, 128);   // 128 = 둘레를 몇 조각으로

4) 유리는 4겹으로 칠하기

WebGL의 투명은 진짜 굴절이 아니라 "겹쳐 칠하기"라서, 유리처럼 보이려면 역할을 나눠 여러 번 그려요.

겹하는 일포인트
안쪽 벽뒷면(BackSide)을 옅게유리 두께가 있다는 느낌
서리(frost)우윳빛 노이즈프로스트 유리의 뿌연 질감
두께 띠가장자리일수록 진하게프레넬: 비스듬히 볼수록 유리를 더 많이 통과
반사빛만 더하기 블렌딩배경을 어둡게 만들지 않고 하이라이트만 얹음
// 프레넬: 표면이 나를 정면으로 보면 d=1, 옆으로 비스듬하면 d→0
float d = abs(dot(normalize(vN), normalize(vV)));
float edge = smoothstep(0.45, 0.05, d);   // 가장자리일수록 1

처음엔 반사 겹을 일반 블렌딩으로 그렸더니 유리가 은색 크롬처럼 보였어요. "빛만 더하고, 투명도(알파)는 건드리지 않는" 커스텀 블렌딩으로 바꿔서 해결했어요.

08

질감: 셰이더로 오돌토돌하게

모델에 들어 있던 텍스처는 평평한 색 그림이라 빛을 받아도 요철이 안 보였어요. 그래서 three.js 기본 재질의 셰이더 코드 중간에 우리 코드 몇 줄을 끼워 넣는 onBeforeCompile을 썼어요.

컬러 바꾸기: 세이지 부분만 골라 칠하기

텍스처 한 장에 세라믹·브라스·유리 색이 섞여 있어서, 픽셀 색을 보고 "세이지 세라믹인 곳"만 골라 새 컬러를 입혀요. 브라스는 따뜻한 색(빨강−파랑이 큼)이라 제외되고, 유리는 너무 밝아서 제외돼요.

float warm = sc.r - sc.b;                                  // 따뜻할수록 큼 → 브라스
float lum  = dot(sc, vec3(0.299, 0.587, 0.114));         // 밝기 → 유리
pzSage = (1. - smoothstep(.09, .16, warm)) * (1. - smoothstep(.62, .70, lum)) * …;
diffuseColor.rgb = mix(원래색, uTint * 원래색 / 세이지기준색, pzSage);  // 명암은 살리고 색만 교체

요철: 노이즈로 법선(normal) 흔들기

빛은 표면의 법선 방향으로 밝기를 계산해요. 실제로 모양을 울퉁불퉁하게 만들지 않고, 법선만 노이즈로 살짝 기울이면 오돌토돌해 보여요(범프 매핑). 고운 입자 + 큰 얼룩 + 드문드문 파인 핀홀을 섞었어요.

float ceramicHeight(vec3 p){
  float g = vnoise(p*260.)*.55 + vnoise(p*120.)*.35 + vnoise(p*30.)*.6; // 고운 결 + 중간 결 + 얼룩
  return g - pits(p*48.)*1.6;                                        // 핀홀은 움푹
}
normal = bumpPerturb(normal, ceramicHeight(vObj) * 0.0016, faceDirection);

노이즈 좌표로 화면 좌표가 아니라 물체 좌표(vObj)를 쓴 게 포인트예요. 그래서 물체가 돌아도 질감이 물체에 붙어서 같이 돌아요.

09

부드러운 움직임의 비밀: 댐핑

스크롤은 뚝뚝 끊겨서 들어와요. 이 값을 3D에 그대로 꽂으면 모래시계가 덜컥거려요. 그래서 값을 두 벌로 나눠요. target은 "가고 싶은 곳", state는 "지금 있는 곳". 매 프레임 남은 거리의 일정 비율만큼만 다가가요.

assets/js/scene.js · frame()

const dt = Math.min(clock.getDelta(), 0.05);
const k  = 1 - Math.pow(0.0009, dt);      // 프레임레이트와 무관한 비율 (60fps든 120fps든 같은 속도)
for (const key of ['x', 'y', 'scale', 'flip', 'cap', 'explode'])
  state[key] += (target[key] - state[key]) * k;
flip.rotation.z = state.flip;
renderer.render(scene, camera);
requestAnimationFrame(frame);

컬러 변경도 똑같이 color.lerp(목표색, k)로 섞어서 색이 스르륵 바뀌어요. 아래 10장 실습에서 "댐핑 끄기"를 눌러 차이를 직접 느껴보세요.
